# Проверка качества Telegram Stories

Цель: найти параметры экспорта, которые уменьшают потерю качества после публикации сторис с телефона.

Границы: исследование официальных источников Telegram, отдельные тестовые MP4 на рабочем столе и сравнение результатов. Дополнительно: отдельный экспериментальный плагин exteraGram для обхода локальной конвертации подготовленного MP4. Код оптимизатора, текущие профили Stealth и Max, исходные видео не меняются. Новые зависимости не нужны.

Исходные наблюдения:
- Исходник 0926 (2).mp4: 1080x1920, 120 fps, 17.40 Мбит/с видео.
- Первый экспорт сторис: 720x1280, около 60 fps, 3.57 Мбит/с видео.
- Подготовленный 1080p60 после публикации: 720x1280, 60 fps, 3.53 Мбит/с видео.
- try1.mp4 и try2.mp4 побайтово совпадают. Патч счетчика кадров не дал отличимого сохраненного результата. Причина совпадения не установлена.
- Пользователь переносит видео как файл, публикует с телефона с Premium. В предпросмотре качество нормальное, опубликованная версия заметно хуже.

Критерии локальной готовности:
- Существенные выводы подкреплены ссылками на официальные документы или исходники с указанием применимости.
- Подготовлены отдельные варианты с обычным корректным контейнером и понятными различиями параметров.
- Файлы проверены по разрешению, временным меткам, длительности, реальному битрейту и полному декодированию.
- Контрольные кадры просмотрены. Звук и синхронизация не меняются без необходимости.
- У пользователя есть порядок публикации и имена для сохранения результатов.
- Записаны ограничения проверки и выполнена проверка текста.

Готовность тестовых файлов не означает улучшение опубликованной сторис. Это проверяется только после загрузки и сравнения сохраненных результатов.

## Плагин exteraGram

Пользователь предложил проверить обход обязательной конвертации через плагин. Целевой клиент: exteraGram с поддержкой Python-плагинов. Пользователь сейчас публикует через AyuGram на Android, предположительно Vivo Neo 10; версия клиента неизвестна.

Границы плагина:
- Действует только при включенном плагине на подготовленную видеосторис storycopy_*.mp4 без монтажа, 720x1280 H.264/AAC, до 30 МБ.
- Не меняет обычные сообщения, фото, съемку камерой и сторис с обрезкой, фильтрами, наложениями или измененным звуком.
- Поддержка подтверждается по исходникам клиента и документации API. При несовместимости остается штатная обработка.
- Плагин отключается штатным механизмом клиента, не требует внешних пакетов и не публикует ничего сам.
- Проверяются отказ при неподходящем вводе, сохранение других сценариев, очистка перехватов и диагностика.
- Проверка на настоящем Android и результат публикации обязательны для заявления о работающем обходе. До них сборка считается экспериментальной.

## Совместимость SDK

Текущая ошибка: установка Story Copy Test заблокирована требованием SDK >=1.4.4.3 при установленном 1.4.3.3. Проверить используемый API, воспроизвести отказ минимальным тестом метаданных, исправить нижнюю границу при достаточных основаниях и выпустить 0.1.1. Проверку интерфейса конвертера при загрузке сохранить. Установку и выполнение на телефоне не считать проверенными локальными тестами.

## Диагностика загрузки плагина

После установки 0.1.1 клиент показывает Unavailable: app interface not supported. Обход в try3 не включился. Подготовить 0.1.2 с указанием этапа отказа, отсутствующего поля или обнаруженной сигнатуры. Сохранить проверки совместимости и запрет на неизвестный интерфейс. Сначала воспроизвести потерю причины ошибки тестом, затем проверить подробную диагностику. Работа обхода требует отдельного теста на устройстве.

## Java reflection в установленном SDK

На телефоне 0.1.2 завершается на method discovery с AttributeError: type. Поддержать два представления класса: готовый объект java.lang.Class и Python-обертку Java-типа. Для обертки использовать документированный Chaquopy getClass и проверить полное имя полученного класса. Сначала воспроизвести отказ тестом. Не менять сигнатуру конвертера и ограничения копирования. Проверка загрузки на телефоне остается обязательной.
