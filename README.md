# TikTok Prep Tool

Локальная подготовка видео для TikTok: перекодирование через ffmpeg и правка
MP4-контейнера. Python со стандартной библиотекой, без облака и телеметрии.

**by youpzdev** - [Telegram](https://t.me/youpzlabnsfw) | [TikTok](https://www.tiktok.com/@youpzdev)

Софт бесплатный. Условия использования: [некоммерческая лицензия](LICENSE).

## Что сейчас проверено

Новый Stealth повторяет наблюдаемые параметры файла, который, по сообщению
пользователя, сохранил высокое качество после обработки другим инструментом и
публикации. Локально проверены структура контейнера, декодирование видеопотока
и сохранность реальных аудиосэмплов при патче. Результат публикации файла,
созданного этой версией утилиты, ещё не проверен.

TikTok сам выбирает, как обработать загруженное видео. Совпадение метаданных
с образцом не гарантирует ни разрешение, ни FPS, ни охваты. Настройки чужого
кодировщика известны не полностью; побайтовое совпадение всего файла не заявляется.

## Запуск

Нужны Python 3 и ffmpeg. Python-пакеты устанавливать не требуется.

Для установки ffmpeg в Windows:

```
winget install Gyan.FFmpeg
```

Утилита ищет ffmpeg и ffprobe в PATH, установке winget и папке `bin/` рядом
с приложением.

Открой `start.bat` или запусти `py -3 app.py`. В браузере откроется
`http://127.0.0.1:8765`. Добавь файлы или папку, выбери режим и нажми
"Обработать видео". Файлы также можно перетащить в окно браузера.

Если порт занят другим приложением, сервер выберет следующий свободный.
Повторный запуск использует уже работающий экземпляр.

## Режимы

Параметры по умолчанию:

| Параметр | Stealth | Max |
|---|---|---|
| Размер | короткая сторона до 1080, длинная до 1920 | короткая сторона до 2160, длинная до 3840 |
| FPS | не выше исходного и 60, возможна дробная частота | без ограничения профилем |
| Видео | всегда H.264 Main L5.2 | копирование подходящего H.264 8 бит; иначе H.264 High |
| Битрейт | от размера и длительности входного файла | при перекодировании 0.26 бита на пиксель |
| Звук при перекодировании | AAC LC, 48 кГц, стерео, 200 кбит/с | AAC LC, 48 кГц, стерео, 320 кбит/с |

Разрешение не увеличивается. Отсутствующий звук не создаётся.

### Stealth

FPS вычисляется как число видеокадров, делённое на длительность контейнера из
ffprobe, затем ограничивается исходной частотой и лимитом профиля. Если расчёт
даёт снижение больше 5% или исходные данные отсутствуют, используется исходный
FPS с тем же ограничением. Поэтому выход может иметь, например, 59.357677 FPS
вместо 60. При дробной частоте временные метки видео немного растягиваются.

Целевой видеобитрейт равен `размер входного файла * 8 / длительность mvhd`,
с округлением вниз до кбит/с. Если длительность `mvhd` неизвестна, берётся
длительность ffprobe. При отсутствии пригодных данных запасной расчёт использует
0.232 бита на пиксель. По умолчанию `maxrate` вдвое больше цели, `bufsize` втрое.
Это расчёт настроек кодирования, фактический битрейт готового потока может отличаться.

Кодирование использует Main L5.2, настройку x264 refs=1 и до трёх B-кадров.
Максимальный интервал ключевых кадров составляет примерно две секунды, смена
сцены может дать дополнительный ключевой кадр. Вместо служебной строки x264
у ключевых кадров записывается SEI `evc0 v1.4.2.2-20260920`. `compressorname`
содержит `Lavc libx264`, боксы `btrt` сохраняются. Тег `©too` получает компактный
JSON с `libevc=0`, `trans_type=-2`, целевым и максимальным битрейтом.

При включённой опции "Фиктивные аудиосэмплы":

- Аудиодорожка остаётся одна. К каждому реальному AAC-сэмплу добавляется девять
  фиктивных, суммарное число сэмплов растёт в десять раз.
- Фиктивные сэмплы занимают по восемь байт с содержимым `0000000400000000`
  и длительностью один тик. Они лежат одним чанком после MP4-боксов, вне `mdat`.
- `mdhd` и `tkhd` сохраняют реальные длительности, а сумма `stts` включает
  фиктивный хвост. `edts` удаляется из обеих дорожек; `mvhd` версии 1 получает
  значение неизвестной длительности.
- Пустой `free` перед `mdat` удаляется, смещения чанков пересчитываются.
  Реальные видео- и аудиобайты на этом этапе не меняются.

Фиктивный хвост не является нормальным AAC-звуком и вызывает ошибки его
декодирования. Это часть экспериментального контейнера; её нельзя выдавать
за проверку исправности всего аудиопотока. Реальные сэмплы проверяются отдельно.

Если опция выключена или в исходнике нет звука, фиктивного хвоста нет,
длительности остаются обычными, списки правок сохраняются. Профиль кодирования
Stealth и его метаданные при этом остаются выбранными.

### Max

Max сохраняет прежнюю обработку. Подходящее H.264 8 бит копируется без повторного
кодирования изображения. Если требуется другой размер или формат, запускается
перекодирование; при ошибке копирования также используется перекодирование.

Старая маскировка удаляет SEI x264 и `btrt`, меняет `compressorname` и `©too`.
При включённой опции фиктивного звука добавляется отдельный раздутый клон
аудиодорожки. Эти действия относятся к Max и не описывают новый Stealth.

## Настройки

Переменные окружения задаются до запуска. Полный набор находится в `app.py`.

| Переменная | Назначение |
|---|---|
| `TT_MODE` | режим по умолчанию: `stealth` или `max` |
| `TT_PORT` | начальный порт, по умолчанию 8765 |
| `TT_S_SHORT`, `TT_S_LONG`, `TT_S_FPS` | ограничения Stealth |
| `TT_S_MAXRATE`, `TT_S_BUFSIZE` | явные ограничения битрейта вместо множителей 2 и 3 |
| `TT_S_PRESET`, `TT_S_REFS`, `TT_S_LEVEL`, `TT_S_X264`, `TT_S_ABR` | параметры кодировщика Stealth |
| `TT_M_REENCODE` | поведение Max: по умолчанию `auto` |
| `TT_M_BPP`, `TT_M_CRF`, `TT_M_MAXRATE`, `TT_M_BUFSIZE` | параметры перекодирования Max |
| `TT_GHOST` | множитель фиктивных сэмплов по умолчанию, 10 |
| `TT_BRAND` | значение тега artist |
| `TT_SEI`, `TT_MASK_MAXRATE` | метаданные старой маскировки Max |

## Результат

Готовые файлы сохраняются рядом с исходником в `tiktok_ready/` под именем
`<имя>_tiktok.mp4`. Файлы, переданные через браузер, сначала копируются в
`incoming/`, их результат попадает в `incoming/tiktok_ready/`.

Обработка выполняется на компьютере. Утилита не публикует видео, не отправляет
его во внешние сервисы и не собирает телеметрию.

## Почему алгоритм изменился

В августе 2026 года старый вариант дал успешную публикацию в 1080p60, но в
сентябре пользователь получил 480p30. Сравнение с новым успешным образцом
показало Main L5.2, сохранённый `btrt`, SEI и одну раздутую аудиодорожку вместо
клона. Старое предположение, что успешная публикация требует удаления всех
SEI и `btrt`, этим сравнением не подтверждается.

Причина разницы качества после публикации пока не установлена. Текущий
Stealth воспроизводит наблюдаемое сочетание параметров для следующей проверки.
