# TikTok Prep Tool

Локальная подготовка видео под TikTok: лёгкое сжатие + патч MP4-контейнера.
Качество не шакалится, каждый файл уникален для антиплагиата.

Python stdlib + ffmpeg · без облака и телеметрии

## 💊 Проблема

Веду тик-ток аккаунт, публикую эдиты по определённой тематике. И столкнулся с
максимально тупейшей проблемой — **тик ток жёстко жрёт качество**. Не сжимает, а
именно жрёт. Из видео формата 4K/60fps на выходе получалось в лучшем случае
720p с 30fps.

## 🔍 Поиск решения

### Попытка 1 — заливать через TikTok Studio

Самое тупое решение, которое взбрело в голову первым. Спустя пару попыток понял,
что сути это не меняет. А самый подкол в том, что заливая видос с устройства, он
остаётся **в кэше** — у тебя он показывается чётко, а у других шакально.
Противная подстава.

Гуглил готовые решения — есть платные, есть бесплатные, но спорные: надо заливать
видос на левый сайт, ничего толком не объясняют, и спустя ожидание выдают
изменённое видео с применённым патчем. Размер при этом за счёт компрессии сильно
падает.

### Попытка 2 — свой конвертер

Написал конвертер, который сжимал битрейт, менял кодек и даунгрейдил видос под
FullHD: с **86 МБ до 15 МБ**. Битрейт тоже поменялся. Но, на удивление, **это не
помогло** — после публикации видос всё равно получался всратым.

### Попытка 3 — патч метаданных ✅

Полез копаться в метаданных патченных видео и заметил интересную закономерность.
Условно, в исходном видосе **1073 кадра**, а в файле написано, что их **в 10 раз
больше**. Этой штуки я не учёл до этого.

Подкрутил свой софт: приложуха убирает все отметки, обходит систему повторного
залива контента и вписывает свой тег с уникальным номером, чтобы каждый видос был
уникальным. И, барабанная дробь... **это прокатило.**

## 🤔 Почему это работает (гипотеза)

Точной причины я не знаю, утверждать ничего не буду — это вообще не мой стек. Но
предположу следующее.

TikTok, похоже, оценивает необходимость компрессии **по битрейту**:

| | Что видит TikTok | Реакция |
|---|---|---|
| **Без патча** | 16 МБ ÷ 18 сек ≈ **7.5 Мбит/с** | «жирно» → ужимает сразу же |
| **С патчем** | 16 МБ ÷ «178 сек» ≈ **0.7 Мбит/с** | «и так убитое» → не трогает |

Из-за раздутого счётчика кадров файл прикидывается длинным и тощим. Алгоритм
решает, что видео и так никакое по качеству, и **не трогает его**. А внутри лежит
честное 1080p — оно и уходит в ленту почти нетронутым.

## ⚙️ Что делает софт

**Шаг 1 — компрессия.** Даунскейл во вписывание в кадр TikTok (короткая сторона
≤1080, длинная ≤1920; 2160×2160 → 1080×1080) + x264 high / preset medium / CRF 22
/ VBV 15 Мбит/с + аудио AAC 48 кГц. Метаданные обнуляются и переписываются под
брендинг с уникальным ID. **~89 МБ → ~16 МБ.**

**Шаг 2 — патч контейнера** ([mp4inflate.py](mp4inflate.py)) — правка боксов MP4
напрямую, без повторного кодирования:

1. **Раздувание счётчика кадров** — в `stsz` добавляются ×9 фиктивных сэмплов
   размера 8, в `stts` — entry `(9657, 256)`. Контейнер показывает ×10 кадров.
2. **Фиктивные чанки** — в `stco` добавляется по одному чанку на каждый фейковый
   сэмпл (все указывают на хвостовой `free`-бокс), `stsc` получает entry
   `(real_chunks+1, 1, 1)`. `mdat` при этом не растёт, а реальные оффсеты
   согласованно сдвигаются на рост `moov`.
3. **Чистка отпечатка** — 32-байтное поле `compressorname` в `stsd` обнуляется,
   в теги пишется уникальный ID вида `<timestamp>_<hex>` — двух одинаковых
   файлов не бывает даже из одного исходника.

Параметры вынесены в константы вверху `app.py`: `FRAME_MULTIPLIER`, `CRF`,
`MAXRATE`, `PRESET`, `AUDIO_BITRATE`, `BRAND`.

## 🚀 Запуск

Двойной клик по `start.bat` (или `python app.py`) — откроется страница
`http://127.0.0.1:8765`. **Загрузил видео → нажал START → забрал результат.**

Требуется **ffmpeg** (ставится один раз):

```
winget install Gyan.FFmpeg
```

Приложение само находит ffmpeg из winget, PATH или папки `bin/` рядом.
Python-зависимостей нет вообще — только стандартная библиотека.

## 📦 Результат

Файлы кладутся рядом с исходником в подпапку `tiktok_ready/` с именем
`<имя>_tiktok.mp4`. Перетащенные в браузер файлы копируются в `incoming/`,
результат — в `incoming/tiktok_ready/`.

Вся обработка **локальная**: ничего никуда не заливается, без телеметрии и
внешних серверов.
