# TikTok Prep Tool

Готовит видео под TikTok по **itzcrih-методу**: сначала лёгкая компрессия
(размер падает в разы, качество почти без потерь), затем патч MP4-контейнера —
файл выглядит для антиплагиата/дедупликации как новый.

## Запуск

Двойной клик по `start.bat` (или `python app.py`) — откроется страница
`http://127.0.0.1:8765`. Загрузил видео → нажал **START** → получил результат.

Требуется **ffmpeg** (ставится один раз): `winget install Gyan.FFmpeg`.
Приложение само находит ffmpeg из winget, PATH или папки `bin/` рядом.

## Что делает пайплайн

**Шаг 1 — компрессия** ([build_command](app.py)): даунскейл во вписывание в кадр
TikTok (короткая сторона ≤1080, длинная ≤1920; 2160×2160 → 1080×1080) + x264
high / preset medium / CRF 22 / VBV 15 Мбит/с + аудио AAC 48 кГц. Метаданные
обнуляются и переписываются под брендинг с уникальным ID. ~89 МБ → ~16 МБ.

**Шаг 2 — патч контейнера** ([mp4inflate.py](mp4inflate.py), точная схема itzcrih):

1. **Раздувание счётчика кадров** — в `stsz` добавляются ×9 фиктивных сэмплов
   размера 8, в `stts` — entry `(9657, 256)`. Контейнер показывает ×10 кадров.
2. **Фиктивные чанки** — в `stco` добавляется по одному чанку на каждый фейковый
   сэмпл (все указывают на хвостовой `free`-бокс), `stsc` получает entry
   `(real_chunks+1, 1, 1)`. `mdat` при этом не растёт; реальные оффсеты сдвигаются
   на рост `moov`.
3. **Чистка отпечатка** — 32-байтное поле `compressorname` в `stsd` обнуляется.

Коэффициент раздувания и параметры компрессии — константы вверху `app.py`
(`FRAME_MULTIPLIER`, `CRF`, `MAXRATE`, `PRESET`, `AUDIO_BITRATE`, `BRAND_TAGS`).

## Результат

Файлы кладутся рядом с исходником в подпапку `tiktok_ready/` с именем
`<имя>_tiktok.mp4`. Перетащенные в браузер файлы копируются в `incoming/`,
результат — в `incoming/tiktok_ready/`.

Вся обработка локальная, без телеметрии и внешних серверов.
